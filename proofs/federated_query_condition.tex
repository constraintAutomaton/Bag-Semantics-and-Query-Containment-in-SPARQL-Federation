\paragraph{Intuition.}
Classical containment asks whether $Q_1$'s results are a subbag of $Q_2$'s on every database.
Federated containment must additionally track \emph{where} each subquery is sent, because different federation members hold independent data.
If $Q_1$ sends a pattern to federation member $\mathit{:a}$ and $Q_2$ sends the same pattern to a different federation member $\mathit{:b}$, no containment claim can be made without knowing the relationship between their contents---a relationship this paper does not assume.
Containment can therefore only be established when $Q_2$ queries the same federation member as $Q_1$ with a containing subquery (condition~$B$).

The local, non-federated part of each query behaves as in single-source containment: if $Q_1$'s local part returns results that are not a subbag of $Q_2$'s local results on some \ac{KG}, no \texttt{SERVICE} call can compensate, since federation members hold independent data (condition~$A$).

Containment of individual \texttt{SERVICE} calls alone is not sufficient: even if each call of the contained query is contained in the corresponding call of the containing query, the queries are not contained if the combining operation differs---a join in one and a union in the other yield incomparable result bags.
For queries combining subqueries by \texttt{UNION} over federation members (\acp{UCFQ}), the \ac{BFR} (\Cref{sec_bag_federation_reduction}) must first be applied: each \ac{UCFQ} is rewritten as a \ac{CQ} over a \ac{BKG}, and containment then reduces to \ac{CQ} bag-semantic containment over that \ac{BKG}, a decidable problem addressed by the results in \Cref{tab_decidable_containment_bag_bag_set}.

Finally, on any database $G$ where some federation member $f' \in F_1$ returns the empty bag for a $Q_1$ \texttt{SERVICE} call, $Q_1$'s result is the empty bag, which is trivially a subbag of $Q_2$'s result.
Similarly, if $\eval{\mathit{QO}(Q_1)}{G} = \emptyset$, the join with any \texttt{SERVICE} call result is also the empty bag, so $Q_1$'s result is the empty bag and containment holds trivially.
Conversely, if $Q_2$ were to contact a federation member $f \notin F_1$, that extra \texttt{SERVICE} call would be joined into $Q_2$'s result; since $f$'s data is independent, it may have no compatible binding for some solution mappings, dropping them from $Q_2$ (in the extreme, emptying it) on databases where $Q_1$ still returns them, breaking containment.
Containment therefore requires $F_2 \subseteq F_1$.

\begin{proposition}\label{prop_federated_containment}
Let $Q_1$ be a query over a federation $F_1$ and $Q_2$ a query over a federation $F_2$.
Then:
\[
Q_1 \sqsubseteq Q_2 \iff \bigl((F_2 \subseteq F_1) \land A \land B\bigr)
\]
where $\sqsubseteq$ on result bags denotes bag containment; $F_i$ is the federation of query $i$; and $A$ and $B$ are defined as follows:
\[
A = \forall G \in \mathcal{G} \colon \eval{\mathit{QO}(Q_1)}{G} \sqsubseteq \eval{\mathit{QO}(Q_2)}{G}
\]
\begin{align*}
B = \forall f \in F_1,\, \forall G \in \mathcal{G} \colon \quad
    &\bigl( f \in F_2 \land \eval{\mathit{QS}(Q_1, f)}{G} \sqsubseteq \eval{\mathit{QS}(Q_2, f)}{G} \bigr) \\
    &\lor\ \bigl( \exists f' \in F_1 \colon \eval{\mathit{QS}(Q_1, f')}{G} = \emptyset \bigr) \\
    &\lor\ \bigl( \eval{\mathit{QO}(Q_1)}{G} = \emptyset \bigr)
\end{align*}
\end{proposition}

\begin{proof}
$(\Leftarrow)$ Assume $(F_2 \subseteq F_1) \land A \land B$.
By $A$, the local part $\mathit{QO}(Q_1)$ is contained in $\mathit{QO}(Q_2)$ on every \ac{KG}.
By $B$, for any database $G$: either every \texttt{SERVICE} call $\mathit{QS}(Q_1, f)$ has a matching call at the same member in $F_2$ such that $\mathit{QS}(Q_1, f) \sqsubseteq \mathit{QS}(Q_2, f)$, or some \texttt{SERVICE} call $\mathit{QS}(Q_1, f')$ returns the empty bag on $G$, or $\eval{\mathit{QO}(Q_1)}{G} = \emptyset$; in the latter two cases $Q_1$'s result is the empty bag and $Q_1 \sqsubseteq Q_2$ holds.
In the first case, since \texttt{JOIN} is monotone~\cite{w3SPARQLQuery}, if each part of the contained query is a subbag of the corresponding part of the containing query, the join result of the contained query is also a subbag of that of the containing query.
Hence $Q_1 \sqsubseteq Q_2$.

$(\Rightarrow)$ By contrapositive: assume $F_2 \not\subseteq F_1$, or $A$ fails, or $B$ fails.

\emph{Case 1: $A$ fails.}
If $A$ does not hold, then on some \ac{KG} $\mathit{QO}(Q_1)$ produces solution mappings that $\mathit{QO}(Q_2)$ does not produce.
For $Q_1 \sqsubseteq Q_2$ to hold despite $A$ failing, $Q_2$'s federation members would need to complement $\mathit{QO}(Q_2)$ to cover the missing solution mappings across every possible database configuration.
Since federation members hold independent data, this cannot be guaranteed.
Hence $Q_1 \not\sqsubseteq Q_2$.

\emph{Case 2: $B$ fails.}
If $B$ does not hold, then there exist $f \in F_1$ and $G \in \mathcal{G}$ such that either $f \notin F_2$ or $\eval{\mathit{QS}(Q_1, f)}{G} \not\sqsubseteq \eval{\mathit{QS}(Q_2, f)}{G}$, and for all $f' \in F_1$, $\eval{\mathit{QS}(Q_1, f')}{G} \neq \emptyset$, and $\eval{\mathit{QO}(Q_1)}{G} \neq \emptyset$.
For $Q_1 \sqsubseteq Q_2$ to hold despite $B$ failing, $\mathit{QO}(Q_2)$ or another federation member of $Q_2$ would need to cover the missing solution mappings across every possible database configuration.
Since federation members hold independent data, this cannot be guaranteed.
Hence $Q_1 \not\sqsubseteq Q_2$.

\emph{Case 3: $F_2 \not\subseteq F_1$.}
$Q_2$ joins a \texttt{SERVICE} call at some $f \in F_2 \setminus F_1$ not queried by $Q_1$;
since this can restrict $Q_2$'s results and $f$'s data is independent, there exists a database where $Q_1$ returns results that $Q_2$ does not.
Hence $Q_1 \not\sqsubseteq Q_2$.
\end{proof}
