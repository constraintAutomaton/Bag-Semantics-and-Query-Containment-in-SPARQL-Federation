\paragraph{Intuition.}
Classical containment asks whether $Q_1$'s results are a subbag of $Q_2$'s on every database.
Federated containment must additionally track \emph{where} each subquery is sent, because different federation members hold independently chosen data.
If $Q_1$ sends a pattern to federation member $\mathit{:a}$ and $Q_2$ sends the same pattern to a different federation member $\mathit{:b}$, no containment claim can be made without knowing the relationship between their contents---a relationship this paper does not assume.
Containment can therefore only be established when $Q_2$ queries the same federation member as $Q_1$ with a containing subquery (condition~$B$).

The local, non-federated part of each query behaves as in single-source containment: if $Q_1$'s local part returns results that are not a subbag of $Q_2$'s local results on some \ac{KG}, no \texttt{SERVICE} call can compensate, since federation members hold independently chosen data (condition~$A$).

Containment of individual \texttt{SERVICE} calls alone is not sufficient: even if each call of the contained query is contained in the corresponding call of the containing query, the queries are not contained if the combining operation differs---a join in one and a union in the other yield incomparable result bags.
For queries combining subqueries by \texttt{UNION} over federation members (\acp{UCFQ}), the \ac{BFR} (\Cref{sec_bag_federation_reduction}) must first be applied: each \ac{UCFQ} is rewritten as a \ac{CQ} over a \ac{BKG}, and containment then reduces to \ac{CQ} bag-semantic containment over that \ac{BKG}, a decidable problem addressed by the results in \Cref{tab_decidable_containment_bag_bag_set}.

Finally, if $Q_1$ contacts a federation member $f \notin F_2$ such that $Q_1$'s \texttt{SERVICE} call at $f$ returns the empty bag on every possible \ac{KG}, then $Q_1$'s full result is the empty bag, which is trivially a subbag of $Q_2$'s result (the $\emptyset$ disjunct in condition~$B$).
Conversely, if $Q_2$ were to contact a federation member $f \notin F_1$, that extra \texttt{SERVICE} call would be joined into $Q_2$'s result; since $f$'s data is chosen independently, it may have no compatible binding for some solution mappings, dropping them from $Q_2$ (in the extreme, emptying it) on databases where $Q_1$ still returns them, breaking containment. The precondition $F_2 \subseteq F_1$ therefore excludes this case.

\begin{proposition}\label{prop_federated_containment}
Let $Q_1$ be a query over a federation $F_1$ and $Q_2$ a query over a federation $F_2 \subseteq F_1$.
Then $Q_1$ is contained in $Q_2$ if and only if conditions $A$ and $B$ hold:
\[
Q_1 \sqsubseteq Q_2 \iff (A \land B)
\]
where $\sqsubseteq$ on result bags denotes bag containment; $F_i$ is the federation of query $i$; $f$ is a federation member; and $A$ and $B$ are defined as follows:
\[
A = \forall G \in \mathcal{G} \colon \eval{\mathit{QO}(Q_1)}{G} \sqsubseteq \eval{\mathit{QO}(Q_2)}{G}
\]
\begin{align*}
B = \forall f \in F_1, \forall G \in \mathcal{G} \colon \\
\Bigl( f \in F_2 \land \bigl( \eval{\mathit{QS}(Q_1, f)}{G} \sqsubseteq \eval{\mathit{QS}(Q_2, f)}{G}\bigr)\Bigr) \\
	\lor \bigl(\eval{\mathit{QS}(Q_1, f)}{G} = \emptyset\bigr)
\end{align*}
\end{proposition}

\begin{proof}
$(\Leftarrow)$ Assume $F_2 \subseteq F_1$ and that $A$ and $B$ hold.
By $A$, the local part $\mathit{QO}(Q_1)$ is contained in $\mathit{QO}(Q_2)$ on every \ac{KG}.
By $B$, each \texttt{SERVICE} call $\mathit{QS}(Q_1, f)$ in $Q_1$ either has a matching call $\mathit{QS}(Q_2, f)$ at the same federation member such that $\mathit{QS}(Q_1, f) \sqsubseteq \mathit{QS}(Q_2, f)$, or returns the empty bag, making $Q_1$'s full result the empty bag and containment trivial.
Since \texttt{JOIN} is monotone~\cite{w3SPARQLQuery}, if each part of the contained query is a subbag of the corresponding part of the containing query, the join result of the contained query is also a subbag of that of the containing query.
Hence $Q_1 \sqsubseteq Q_2$.

$(\Rightarrow)$ By contrapositive: assume $A$ or $B$ fails.

\emph{Case 1: $A$ fails.}
If $A$ does not hold, then on some \ac{KG} $\mathit{QO}(Q_1)$ produces solution mappings that $\mathit{QO}(Q_2)$ does not produce.
For $Q_1 \sqsubseteq Q_2$ to hold despite $A$ failing, $Q_2$'s federation members would need to complement $\mathit{QO}(Q_2)$ to cover the missing solution mappings across every possible database configuration.
Since federation members hold independently chosen data, this cannot be guaranteed.
Hence $Q_1 \not\sqsubseteq Q_2$.

\emph{Case 2: $B$ fails.}
If $B$ does not hold, then there exists a federation member $f \in F_1$ and a \ac{KG} for which $\mathit{QS}(Q_1, f)$ produces a non-empty bag of solution mappings, and either $f \notin F_2$, or that bag is not a subbag of $\eval{\mathit{QS}(Q_2, f)}{G}$.
For $Q_1 \sqsubseteq Q_2$ to hold despite $B$ failing, $\mathit{QO}(Q_2)$ or another federation member of $Q_2$ would need to cover the missing solution mappings across every possible database configuration.
Since federation members hold independently chosen data, this cannot be guaranteed.
Hence $Q_1 \not\sqsubseteq Q_2$.
\end{proof}
