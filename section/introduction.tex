\section{Introduction}

Avoiding redundant computation is a central concern of query optimization.
Query containment is a classical problem underpinning such optimizations, including caching, view selection, query rewriting, and equivalence checking~\cite{Afrati2019-ch1, DOAN201221, Chaudhuri1993}.
Under set semantics, containment has been thoroughly characterized for many query fragments~\cite{Chandra1977, aho1979equivalences, aho1979efficient, Chekuri2000}.
Bag- and bag-set semantic containment have also been studied~\cite{Chaudhuri1993, Afrati2010, khamis2021bag}; however, containment is undecidable for several fragments and some problems remain open.


\acp{KG} have become a widely adopted paradigm for representing and integrating heterogeneous data, supporting applications in scientific data management, enterprise knowledge representation, and the Web of Data.
They are typically encoded as \ac{RDF}, the W3C standard for graph-structured data, and queried with SPARQL, its companion query language.
SPARQL provides federation through the \texttt{SERVICE} operator~\cite{w3SPARQLFederated}, which executes a sub-query at a SPARQL endpoint identified by a URL.
This enables virtual data integration across distributed \ac{KG} sources, allowing heterogeneous data to be queried jointly without centralization.
This is particularly valuable when sources are governed by different policies, maintained by independent parties, or too large to consolidate.
Whether federation members are SPARQL endpoints on an internal network or exposed openly over the Web, federated queries impose substantial computational load on both endpoints and clients.\footnote{The open-Web setting can be fragile. Public SPARQL endpoints frequently experience downtime or performance degradation under load~\cite{buil2013sparql}.}
This cost is especially acute in workflows such as scientific reproducibility studies, where queries are routinely re-executed or iteratively refined.
Query optimization that avoids such re-execution is therefore highly desirable, and query containment is a foundational mechanism for achieving it.

Existing research on SPARQL query containment has focused on set semantics~\cite{WudageChekol2013}.
Yet the SPARQL query language operates under bag-set semantics~\cite{Perez2006, Angles2016}: the underlying database follows set semantics~\cite{w3ConceptsAbstract}, while query operators produce bags\footnote{A bag, or multiset, is similar to a set but allows duplicate elements.}~\cite{w3SPARQLQuery}.
Set-semantic containment does not imply bag-set semantic containment, so existing containment results do not apply to real-world SPARQL query optimization.
For example\footnote{Inspired by \citeauthor{Chaudhuri1993}}, \Cref{fig:bag-set-example} presents a containing query (a query whose results always include those of a contained query, regardless of the database) and a contained query.
The containing query retrieves the ages of all people in the dataset, whereas the contained query refines it to those who have a job.
Under set semantics, the two queries are contained.
Under bag-set semantics, however, projecting away variables can introduce duplicates, which occurs in the example whenever an individual holds multiple jobs.\footnote{An executable example is provided at \url{https://github.com/constraintAutomaton/demo-semantic-query-containment-SPARQL} using the Comunica~\cite{taelman_iswc_resources_comunica_2018} query engine and the Specs~\cite{Spasic2023} SPARQL query containment solver.}

To the best of our knowledge, bag-set semantic SPARQL query containment remains unexplored, and neither has query containment been studied for federated queries.\footnote{Note that QCan~\cite{salas2018canonicalisation} addresses bag-set semantics, but for query equivalence rather than containment, by transforming SPARQL queries into a canonical form and performing syntactic comparison.}

This paper bridges these gaps by giving a decision procedure for query containment under bag-set semantics for federated SPARQL queries with \texttt{SERVICE} clauses.
We additionally cover \ac{UCFQ}, a class in which each disjunct is a \ac{CQ} evaluated over a distinct federation member.
This class strictly extends \ac{CQ} but lies inside \ac{UCQ}.
It is of further interest because it captures \acp{CQ} of federated queries using under automatic source selection~\cite{Cheng2021}.
The procedure relies on \ac{BFR}, a transformation from \ac{UCQ} to \ac{CQ} under bag semantics.
